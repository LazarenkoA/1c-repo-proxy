# 1c_repo_proxy

TCP-прокси между конфигуратором 1С и tcp-сервером хранилища конфигураций.
Прозрачно ретранслирует трафик, позволяет проверять комментарии коммитов,
смотреть, **что именно** помещается в хранилище (код модулей, метаданные),
и запускать внешние команды после каждого помещения (например, синхронизацию с git).

```
Конфигуратор ──> 1c_repo_proxy :1543 ──> crserver :1542 (хранилище)
```

## Сборка

```bat
go build -o 1c_repo_proxy.exe .
```

Требуется Go 1.27 (в `go.mod` закреплён `toolchain go1.27.0`). Если `go` в PATH старше —
тулчейн скачается автоматически; при проблемах с прокси-репозиторием модулей
используйте `GOPROXY=direct`.

## Запуск

```bat
.\1c_repo_proxy.exe --port 1543 --repo localhost:1542
```

В конфигураторе строка подключения к хранилищу: `tcp://<адрес-прокси>:1543/<имя хранилища>`.

### Параметры

| Параметр | Описание |
|---|---|
| `--port`, `-p` | Порт, который слушает прокси |
| `--repo` | Адрес tcp-сервера хранилища (`host:port`, также принимается `tcp://host:port/имя`) |
| `--match` | Регулярное выражение, которое **должно** присутствовать в комментарии коммита |
| `--no-match` | Регулярное выражение, которого **не должно** быть в комментарии коммита |
| `--dump <каталог>` | Дамп всех пакетов конфигуратора + извлечённые исходники (см. ниже) |
| `--on-commit <команда>` | Команда, запускаемая после успешного помещения в хранилище (см. ниже) |
| `--on-commit-dir <каталог>` | Рабочий каталог для команды `--on-commit` |

Комментарий проверяется только у вызовов помещения (`DevDepot_commitObjects`) и
изменения версии (`DevDepot_changeVersion`). При нарушении — пакет в хранилище не
уходит, конфигуратор получает нативную ошибку:

```
.\1c_repo_proxy.exe --port 1543 --repo localhost:1542 --match "^TASK-\d+"
```

## Запуск синхронизации с git после помещения


После каждого успешного помещения асинхронно запускается `cmd /c <команда>`.
Команде передаются переменные окружения:

| Переменная | Содержимое |
|---|---|
| `CRS_REPO` | Имя хранилища (alias из строки подключения) |
| `CRS_USER` | Пользователь хранилища |
| `CRS_COMMENT` | Комментарий коммита |
| `CRS_CALL` | Имя вызова: `DevDepot_commitObjects` или `DevDepot_changeVersion` |

Запуск прокси с хуком:

```bat
.\1c_repo_proxy.exe --port 1543 --repo localhost:1542 --on-commit sync.bat --on-commit-dir D:\git\myconfig
```

Пример `sync.bat` — обновить конфигурацию из хранилища пакетным конфигуратором,
выгрузить файлы в git-рабочую копию и закоммитить:

```bat
@echo off
set BIN=C:\Program Files (x86)\1cv8\8.3.23.1782\bin

rem 1. Обновить конфигурацию базы из хранилища
"%BIN%\1cv8.exe" DESIGNER /F D:\1c\service_base /N Робот /P *** ^
    /DepotUpdateCfg /DepotU Робот /DepotP *** /Out D:\git\sync_update.log -NoTruncate

rem 2. Выгрузить файлы конфигурации в рабочую копию git
"%BIN%\1cv8.exe" DESIGNER /F D:\1c\service_base /N Робот ^
    /ConfigDumpFiles D:\git\myconfig /Out D:\git\sync_dump.log -NoTruncate

rem 3. Закоммитить
cd /d D:\git\myconfig
git add -A
git commit -m "%CRS_COMMENT% (%CRS_USER%)" --author="1c-depot <%CRS_USER%@example.local>"
```

Альтернатива — [gitsync](https://github.com/oscript-library/gitsync) (OneScript):
он сам обходит версии хранилища и выгружает канонические XML; прокси можно
использовать как «будильник» для немедленного запуска синхронизации после
каждого помещения.

Замечание: хук срабатывает в момент **пересылки** коммита в хранилище, не дожидаясь
ответа сервера. Если хранилище отклонит коммит, gitsync просто не найдёт новых версий —
данных в git не попадёт.

## Как это работает внутри

- Транспорт — сырой TCP с XML-сообщениями, разделитель — 4 байта `66 53 B2 A6`.
  Сообщения могут слипаться в одном TCP-чанке — разделитель хранит остаток буфера.
- При нарушении регулярки прокси сам отвечает конфигуратору
  (`<exception reason="406">`) и не пересылает пакет в хранилище.
- Извлечение: `sources.go` — обход контейнера (`harvestTexts`), разбор
  скобкофайлов (`extractFromBracketText`), двоичных модулей (`extractModuleBlocks`);
  `hook.go` — пост-коммит хук.



## Ограничения

- Не работает с файловым вариантом хранилища и http-хранилищем — только tcp.
- Хук `--on-commit` не дожидается подтверждения от сервера хранилища.
- Извлечение исходников покрыто тестами на модуле объекта, модуле формы и
  метаданных справочника; для прочих типов объектов (регистры, обработки и т.п.)
  формат тот же, но при желании добавляйте свежие дампы в `testdata/` и
  расширяйте `harvestTexts`.
